# Exam Security, Offline Answer Sync, and Lucide Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Migrate UI icons to Lucide, make active-exam navigation resistant to casual exits, and synchronize answers after transient network failures without losing student work.

**Architecture:** Keep the four changes in independently testable slices. A deep local-storage queue owns answer persistence and retry mechanics; a small React adapter exposes queue state to the exam UI; a separate exam-security provider owns browser/router lifecycle listeners and exposes one explicit `allowExit()` transition. Lucide migration remains a visual refactor, and browser configuration is kept separate from runtime security logic.

**Tech Stack:** Next.js 16.1.6 Pages Router, React 19.2.4, Bun, Zustand, Axios, `lucide-react`, `bun:test`, Tailwind CSS.

**Spec:** `docs/superpowers/specs/2026-09-23-exam-security-offline-sync-design.md`

## Global Constraints

- Use `lucide-react` named imports for UI control icons; do not add another icon library.
- Keep the decorative illustration in `components/WelcomeBanner.jsx` unchanged.
- Make at most three total answer-save request attempts: the initial request plus two retries.
- Replace the queue entry for a newer answer to the same answer-sheet identifier and question; do not append duplicate entries.
- Keep failed answer payloads in versioned `localStorage` until synchronization succeeds.
- Block exam submission while any answer queue entry remains.
- Security protection is active only while the exam is active and `examInfo.warnEnabled` is true.
- Only successful submission or timer-driven auto-submit may call `allowExit()` and navigate to `/exam/selesai`.
- `beforeunload` is a best-effort browser confirmation, not a guaranteed browser lock.
- Target Chrome/Edge 80, Firefox 73, Safari/iOS 13, and Chrome Android 80-era browsers; IE 11 and Android 4 are out of scope.
- Add a narrowly justified polyfill only if the compatibility audit proves it is required; do not downgrade Next.js or React in this plan.
- Preserve existing answer behavior, backend endpoints, exam timing, and authenticated Axios configuration.
- Do not expose or commit tokens, `.env` values, or generated secrets.

## Review Focus

- A newer answer for the same question must not be removed by a late success response from the older request.
- A terminal network failure must leave the answer recoverable after reload and must not make the submit button silently submit stale data.
- A forced browser back/forward event must not bypass the active-exam guard when `warnEnabled` is true.
- A successful submit or auto-submit must be the only transition allowed to `/exam/selesai`; failed submit must not release the guard.
- A browser without `sendBeacon`, without a reliable `navigator.onLine`, or with damaged local storage must degrade without deleting recoverable answers.

import { describe, expect, test } from "bun:test";
import { createAnswerQueue } from "./answerQueue";

function createMemoryStorage(initial = {}) {
  const values = new Map(Object.entries(initial));
  return {
    getItem: (key) => (values.has(key) ? values.get(key) : null),
    setItem: (key, value) => values.set(key, value),
    removeItem: (key) => values.delete(key),
    values,
  };
}

test("replaces a newer answer instead of creating a duplicate entry", async () => {
  const sent = [];
  const storage = createMemoryStorage();
  const queue = createAnswerQueue({
    storage,
    send: async (payload) => sent.push(payload),
    scheduleRetry: (task) => task(),
    now: () => 1,
  });

  queue.enqueue({
    sheetId: "s1",
    payload: { exam_answer_sheet_id: "s1", exam_soal_id: "q1", answer_chosen_id: "a" },
  });
  queue.enqueue({
    sheetId: "s1",
    payload: { exam_answer_sheet_id: "s1", exam_soal_id: "q1", answer_chosen_id: "b" },
  });
  await queue.flush();

  expect(queue.getState().entries).toHaveLength(1);
  expect(sent).toHaveLength(1);
  expect(sent[0].answer_chosen_id).toBe("b");
});

test("stops after three total attempts and retains the latest payload", async () => {
  let calls = 0;
  const queue = createAnswerQueue({
    storage: createMemoryStorage(),
    send: async () => {
      calls += 1;
      throw new Error("offline");
    },
    scheduleRetry: (task) => task(),
    now: () => 1,
  });

  queue.enqueue({
    sheetId: "s1",
    payload: { exam_answer_sheet_id: "s1", exam_soal_id: "q1", content: "jawaban" },
  });
  await queue.flush();

  expect(calls).toBe(3);
  expect(queue.getState().pendingCount).toBe(1);
  expect(queue.getState().entries[0].payload.content).toBe("jawaban");
});

- [ ] **Step 3: Implement the queue with lazy storage access**

Implement `createAnswerQueue` with these rules:

- Use a versioned storage key such as `smeduverse-exam-answer-queue-v1`.
- Read storage only when a browser storage object is supplied or when a caller explicitly provides one; importing the module must not access `window` during SSR.
- Store an object containing `version` and `entries`.
- Deduplicate by the `sheetId` scope plus `payload.exam_soal_id`; the `sheetId` is the current exam identifier and is not sent to the backend.
- Reset attempts to zero when replacing a payload.
- Never delete a newer entry because an older in-flight request completed; compare the entry version/updated marker before removal.
- Treat no network response, timeout, and HTTP 5xx as retryable.
- Treat HTTP 4xx/validation responses as non-retryable `failed` entries that retain the payload.
- After the third retryable failure, retain the entry as `queued` and notify subscribers.
- Catch storage read/write errors and report them without deleting the last valid persisted record.
- `scheduleRetry` receives a zero-argument task that starts the next flush attempt; the test injects `task => task()` so the three-attempt limit is deterministic.
- Expose a subscription list and remove a listener when its unsubscribe function is called.
